## 3. The window (`node_performance/contract_window/`)

- [x] 3.1 The data: per epoch `HashMap<NodeId, KindMedians>` (medians only, an epoch read with no nodes not held), the weights at X with X, and the last submission seen. Methods: R at or before an epoch; trimming below `R - 24`; the figure of node n at X, which runs the shared rule (task 1.1) with a hint of `None` and lookups that never fail, and scores the resolved medians with `Weights::score` under the weights at X, returning a named struct (source epoch, medians, `Option<Percent>` score) or `None` without a source; whether X holds data (for fault mode)
- [x] 3.2 Loading, generic over `C: PerformanceQueryClient`: the startup load (`get_last_submission` and the weights at X; with a submission, from its epoch, or X when lower, down to the first epoch holding nodes, then to `R - 24`; failing when none of the first 25 epochs holds nodes), and one poll step (a full load until the window has seen a submission; else a new X: read its weights; a changed last submission: re-page every epoch from the recorded submission's epoch to the new one's, recording the last submission read before the pages; then trim). A step holds the write lock throughout, reads everything before changing anything, and stamps `refreshed_at` on success. An epoch is paged with `get_all_epoch_performance`. The epoch operations run the same poll step; there is no separate reload
- [x] 3.3 The refresher task: waits for the mixnet contract cache, then polls every `contract_polling_interval` under the shutdown token, taking X from the mixnet contract cache's current interval and logging a failed step without stopping
- [x] 3.4 `support/cli/run.rs`: with the flag on, a missing performance contract address fails startup; the window is built over the query client and started. With the switch off a failed first load is logged and left to the refresher. With the switch on the first load must succeed, and a last submission with no data fails startup. `has_performance_data` is unchanged. Drop any `support/nyxd` wrapper left without a caller (`get_full_epoch_performance`, `get_last_performance_contract_submission`)
- [x] 3.5 Tests through a test type implementing `PerformanceQueryClient`, answering `EpochPerformancePaged`, `WeightsAt` and `LastSubmittedMeasurement` from its fields through a `cosmwasm_std` JSON round trip (the PR3 `FakeContract` pattern): a start after an outage holds exactly `[R - 24, R]`, with X held as absent and the weights at X, and pages nothing above R; a last submission whose epoch is empty walks down to R; a load finding nothing in the 25 epochs from its start fails without paging further; a changed last submission re-pages X, which becomes R and trims; an unchanged last submission makes no query beyond its read; a submission landing between the last-submission read and the pages is re-paged by the next step; a new epoch reads the weights at X + 1, pages nothing and drops nothing while R stays; a late chunk for X and the first chunk for X + 1 landing between two polls are both held after the next; a step failing after its first read leaves the window as it was; a contract with no submission yields an empty window.
