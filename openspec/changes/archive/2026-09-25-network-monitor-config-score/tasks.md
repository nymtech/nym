## 6. Computation and materialisation

- [x] 6.1 `materialise_config_scores` in the materialiser: queries the config-score params (`get_mixnet_contract_state_params().config_score_params`) and version history (`get_full_nym_node_version_history`) once via the epoch source's client, builds a `ConfigScoreCalculator`, reads the bonded-node registry + cached capabilities from storage, and batch-inserts. Config values arrive via a new `MaterialiserConfig` bundle (config-first arg), including `minimum_balance` + `chain_interactions_penalty` (the latter added as a config knob here, deferred from 4.5)
- [x] 6.2 Driven from `get_bonded_nym_nodes` (the registry, not the raw bond list). Per the readiness-gate discussion: a node that never described scores unavailable-0 (a true assessment); a described node with an address but no cached capability is DEFERRED (absent, not scored from a guess), so an untrue score is never written and can never be submitted; a described node with no address is penalised (known inability to transact). The scoring loop is extracted into a pure `compute_config_scores` fn for unit testing. nyxd `Coin` is converted to cosmwasm `Coin` (what the shared crate uses) at the boundary
- [x] 6.3 Config score is filed ONLY under the current epoch and NEVER backfilled (Decision 2 / the fresh-start discussion): it is a separate pass in `run()` after `materialise_pending`, not inside the per-epoch aggregate loop - a backfilled past epoch would only get today's state. Also added the `bonded` flag (single migration `05_config_score.sql`): the refresh marks the current bond set bonded and `mark_stale_nodes_unbonded` (last_seen_bonded watermark) flips the rest, so the sweep and materialiser skip definitively-gone nodes
- [x] 6.4 Tests. `compute_config_scores` (pure, no chain/DB): compliant node -> 1.0 with full decomposition; never-described -> unavailable-0; described-but-uncached -> deferred; no-address -> penalised not deferred; the minimum balance is applied at score time (same cached balance, different threshold, no re-query). Storage: `get_bonded_nym_nodes` excludes unbonded; the watermark keeps a re-touched node bonded. Suite 157/157
- Note (post-6 refactor, user-driven): `aggregation/materialiser.rs` became a directory module. A `Materialiser<C>` wrapper owns the single task + the single `MixnetEpochSource<C>` and drives two members it reads the epoch once per tick for: a NON-generic `AggregateMaterialiser` (timing + storage only, its `materialise`/`materialise_pending` borrow `&mut MixnetEpochSource<C>`, take no client) and a `ConfigScoreMaterialiser<C>` holding its OWN cloned query client. `MixnetEpochSource::client()` was deleted (the leak this removed). Behaviour unchanged, so 6.1's "via the epoch source's client" now reads "via its own client"; 6.3's "separate pass in run()" is now the wrapper's `config_scores.materialise` after `aggregates.materialise_pending`
