### VPS Disk Usage & Log Control Guide 

The steps below are for manual cleanup and space reclaim on a VPS hosting a `nym-node`.

<Steps>

###### 1. Identify what is consuming disk space

```sh
df -h
du -xhd1 /var | sort -h
du -xhd1 /var/log | sort -h
find /var -type f -exec ls -lh {} + 2>/dev/null | sort -k 5 -h | tail -n 30
journalctl --disk-usage
```

###### 2. Prune `journald`
- Trim logs by running these commands

```sh
journalctl --vacuum-size=100M
journalctl --vacuum-time=3days
journalctl --disk-usage
```
- Compare the outcome of the last one with the previous check

###### 3. Make `journald` limits persistent

- Create a new file `/etc/systemd/journald.conf` with these hard caps:
```sh
mkdir -p /etc/systemd/journald.conf.d

cat >/etc/systemd/journald.conf.d/limits.conf <<'EOF'
[Journal]
Storage=persistent
Compress=yes

SystemMaxUse=100M
RuntimeMaxUse=50M
SystemMaxFileSize=25M
RuntimeMaxFileSize=10M
MaxRetentionSec=3day

RateLimitIntervalSec=30s
RateLimitBurst=1000
EOF

systemctl restart systemd-journald
```


###### 4. Disable classic `rsyslog`

Prevent duplicate logging as most Ubuntu VPS images run both `journald` and `rsyslog` by default. That duplicates logs into `/var/log/syslog`.

<Callout type="warning" emoji="⚠️">
**Check `fail2ban` first - before you stop anything.** If `fail2ban` reads log files rather than the journal, it watches `/var/log/auth.log`. Once `rsyslog` is stopped nothing writes to that file any more, so `fail2ban` sees no further SSH failures and silently stops banning. No error is raised, it simply never bans again - and keeping the file does not help, because it goes stale. Gateways attract constant SSH scanning, so this matters.

```sh
grep -rE '^[[:space:]]*backend' /etc/fail2ban/jail.local /etc/fail2ban/jail.conf /etc/fail2ban/jail.d/ 2>/dev/null
```

**Empty output means the default applies, which is `backend = auto` - a file backend on most systems.** Treat empty output as "not systemd".

If the backend is not `systemd`, pick one before continuing:

- **Recommended:** set `backend = systemd` in `/etc/fail2ban/jail.local`, then `systemctl restart fail2ban`, and verify with `fail2ban-client status sshd`. After that the rest of this step is safe.
- **Otherwise:** skip this whole step and leave `rsyslog` running. The journald caps in step 3 already bound your disk usage; `rsyslog` duplication costs space but does not break anything.

The Ansible role `rsyslog_disable` makes the same check and refuses to stop `rsyslog` when `fail2ban` needs the files, so the manual path here matches the automated one.
</Callout>

- Only once the check above passes, disable rsyslog:

```sh
systemctl disable --now rsyslog.service || true
systemctl mask rsyslog.service || true
pgrep -x rsyslogd >/dev/null 2>&1 && pkill -9 -x rsyslogd || true
```

- Optional cleanup of the files it used to write:

```sh
rm -f /var/log/syslog /var/log/syslog.1
rm -f /var/log/kern.log /var/log/kern.log.1
rm -f /var/log/ufw.log /var/log/ufw.log.1
rm -f /var/log/auth.log /var/log/auth.log.1
```

<Callout type="info" emoji="ℹ️">
Delete these **after** stopping `rsyslog`, never before. Removing a file a running writer still holds open does not free the space: the kernel keeps the inode alive until the process closes it, so `df` will not move. If `rsyslog` is still running, use `truncate -s 0 <file>` instead.
</Callout>
> Note: Running `logrotate --force /etc/logrotate.conf` may fail after disabling `rsyslog`. That is expected and safe.

###### 5. Reduce `nym-node` log growth

- Create a new dir for a service file controlling `nym-node` logs:

```sh
mkdir -p /etc/systemd/system/nym-node.service.d
```

- Create the service file:

<Callout type="warning" emoji="⚠️">
**Do not use systemd `LogLevelMax=` for this.** `nym-node` writes to stderr, and `journald` stamps everything a service writes to stdout/stderr with `SyslogLevel=` (default `info`). `LogLevelMax=warning` therefore discards **every** line the binary emits - including its errors - and the node appears completely silent while running normally. Filter with `RUST_LOG` instead, which works inside the binary, so warnings and errors still reach the journal.
</Callout>

```sh
cat >/etc/systemd/system/nym-node.service.d/10-logging.conf <<'EOF'
[Service]
# info  = upstream default, keeps packet counters and health-check lines
# warn  = warnings and errors only
# error = errors only
Environment=RUST_LOG=info
LogRateLimitIntervalSec=30s
LogRateLimitBurst=200
StandardOutput=journal
StandardError=journal
SyslogIdentifier=nym-node
EOF

systemctl daemon-reload
systemctl restart nym-node
```

- Confirm the node is still logging. This is the step people skip:

```sh
sleep 30
journalctl -u nym-node --since "-1 min" --no-pager | tail -5
```

If that is empty while `systemctl is-active nym-node` says `active`, logging is broken, not quiet. Check for a stale `LogLevelMax=` in `/etc/systemd/system/nym-node.service.d/`.

###### 6. Optional: Tune kernel writeback

- This config reduces burst disk pressure

```sh
cat >/etc/sysctl.d/99-writeback-tuning.conf <<'EOF'
vm.dirty_writeback_centisecs=1500
vm.dirty_expire_centisecs=6000
EOF

sysctl --system
```

###### 7. Enable periodic Trim

- This reclaims the free space

```sh
systemctl enable --now fstrim.timer
fstrim -av
```

###### 8. Reclaim apt cache space

- APT cache can become heavy too, reclaim that space by these commands:

```sh
apt-get clean
apt-get -y autoremove
rm -rf /var/lib/apt/lists/*
mkdir -p /var/lib/apt/lists
```

###### 9. Verify final state

- Check disk space now after the cleanup
```sh
df -h
journalctl --disk-usage
```
</ Steps>
