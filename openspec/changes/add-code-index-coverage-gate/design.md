# Design: Add Code-Index Coverage Gate

## Context

`ROOTS` in `documentation/indexed-sources.mjs` is the canonical list of source trees the code index is built from: `generate-code-index.mjs` walks exactly those paths and embeds them into `code-index.json`, and the MCP `search_code` tool answers only from that index. A crate outside `ROOTS`, or one that silently falls out of the index, returns nothing rather than an error, so the only way to know a root is reachable is to test it.

The test exists (the "Index coverage" group in `check-mcp-server.sh`) but its probes are a second list, maintained by hand, with nothing tying it to `ROOTS`. The two have drifted: 8 of the 20 current roots have no probe. Adding `nym-vpn-client` under `add-shared-retrieval-index` compounds it, since `ROOTS` and the check are single-repo.

The probes cannot simply be generated by looping over `ROOTS`, because each probe uses a *discriminating symbol query* chosen so exactly one crate matches; `check-mcp-server.sh` documents two cases where a generic query decayed as the corpus grew and started matching the wrong crate. So the fix is not to remove the hand-written list but to stop it drifting from `ROOTS`.

## Goals / Non-Goals

**Goals:**

- The set of roots verified citable is derived from `ROOTS`, so a new root cannot pass CI unverified.
- Every currently-uncovered root gets a probe.
- Coverage is repo-aware, so no producer repo is silently omitted.

**Non-Goals:**

- Auto-generating probe queries (they stay human-authored).
- Deciding which roots belong in the corpus (that is the `add-shared-retrieval-index` Q3 spike).

## Decisions

1. **Split static completeness from live citability.** Static completeness ("every root has a probe") is pure data — `ROOTS` versus the probe map — needs no deployment, and runs as a **unit test** at PR time, where drift is cheapest to catch. Live citability ("the probe actually returns a hit") needs a running deployment and stays in `check-mcp-server.sh`. This is the key change: the drift that matters is caught without a deploy.

2. **Probe data lives in a sibling file, not in `indexed-sources.mjs`.** That file is traced into the `/api/mcp` lambda and parsed at every cold start (`outputFileTracingIncludes`), so co-locating test queries there ships and re-parses test data in production. A separate `documentation/scripts/index-coverage-probes.mjs` is imported by the unit test and read by the shell check, and is never in the lambda trace.

3. **Queries stay human-authored.** A probe is `{ root: { label, query } }`; the query is the discriminating symbol a human picks. The gate enforces that a query *exists* per root, not what it says.

4. **A probe covers a root when its path fragment is at or under that root.** Today some probes target a subpath (`sdk/rust/nym-swizzle` covers `sdk/rust`; `clients/` covers both `clients/native` and `clients/socks5`). The completeness check treats a root as covered if any probe's path fragment is equal to or nested under it, so subpath probes keep working.

5. **Repo-awareness reuses the shared-index roots shape.** Rather than invent a second per-repo roots format, the probe map and both checks iterate the per-repo roots structure that `add-shared-retrieval-index` defines (task 3.1, informed by the Q3 spike 2.3). This part is sequenced after that shape exists; the single-repo drift fix does not wait for it.

## Open Questions

- Where the completeness unit test sits in the existing vitest suite, and whether it reports all missing roots at once or fails on the first.
- Whether to also assert the reverse (a probe whose root is not in `ROOTS`), catching a probe left behind after a root is removed. Low stakes; likely a warning, not a failure.

## Risks / Trade-offs

- **A stricter gate can block a deploy or a PR for a missing probe.** That is the intent — the whole point is that a new root cannot land uncited — but it means widening `ROOTS` now also requires writing a probe. The cost is one line of human-authored query per root, which is the judgement that made the probes trustworthy in the first place.
- **The repo-aware part is coupled to another change.** If the shared-index roots shape shifts, this change's task 2 follows it. Mitigated by landing the single-repo fix independently first.

## Migration Plan

1. Add the probe data file and the static completeness test against today's flat `ROOTS`; backfill the 8 missing probes; port `check-mcp-server.sh` to read the data file; revert the interim caveat in `indexed-sources.mjs`. (Single-repo, lands now.)
2. Once `add-shared-retrieval-index` lands the per-repo roots shape, extend the probe map and both checks to iterate producer repos, and verify a repo with no probes fails completeness rather than being omitted.
