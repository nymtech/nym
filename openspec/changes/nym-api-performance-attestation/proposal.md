## Why

The performance contract commits every node's newest score to a digest, and `nym-performance-client` can verify that committed set at a height (`performance-retrieval-client`), but nothing produces attested snapshots of it, so a client without a chain connection has nothing to verify against, and nym-api publishes nothing from it: in contract mode the node status refresher writes an empty annotation map, so every node would be published at 0. This change makes every nym-api a producer of attested performance snapshots, as it already is for the directory, and publishes the verified routing figure as each node's performance in contract mode, the last piece before the switch can be turned on. It also stops nym-api serving, rewarding or selecting from caches it has not built yet, which today publishes performance 0 for every node for minutes after some restarts.

## What Changes

- **Every nym-api produces attested performance snapshots.** At the directory contract's snapshot cadence, it reads the performance contract's committed set at the boundary height through `PerformanceClient` under a proven anchor, signs a `DigestSnapshot` for it, retains the newest few, and serves them under `/v1/performance` (`/snapshot/latest`, `/snapshot/{height}`, `/entries/{height}/records`), mirroring `/v1/directory`. The identity map at a height is the directory's, since both are the mixnet bonds at that height, so clients take it from `/v1/directory/entries/{height}/node-identities`. It runs on every nym-api, independent of the switch, so it is live during the shadow period. The performance contract address is assumed present: a missing one fails startup.
- **One snapshot mechanism for both contracts.** The directory producer's cache, refresher and state become generic over the record type; the directory moves onto them with its routes and wire format unchanged, and performance is the second user. The cadence, retention, settle lag and polling interval come from `[directory.debug]`, shared by every attested contract. The directory's empty `ParsedDirectory` placeholder is dropped.
- **Settle-lag fix.** The directory's latest snapshot is currently promoted after `retention_count` (3) blocks instead of `settle_lag` (default 10), because startup passes the wrong knob. It now uses `settle_lag`. Behaviour change on a deployed route: the directory's latest snapshot advances 7 blocks later.
- **Unproven medians beside each snapshot.** At each snapshot height the producer also reads the weights in force and the per-node medians of the newest two epochs among the committed entries, for the annotation routes only, skipping the pages whenever the contract's last submission has not changed. They are never signed and never served on `/v1/performance`.
- **Published performance in contract mode is the verified routing figure.** The node status refresher builds annotations from the latest settled performance snapshot: `performance_score` is the node's committed score, so every topology route publishes a figure clients can verify against the digest. The sub-scores carry the unproven medians (config, stress, liveness) and a routing figure recomputed from them, for the annotation routes. A node never measured has no annotation and is served 0. With no settled snapshot the map is left as it is. This replaces 4a's empty map. The temporary `liveness-divergence` route answers 503 in contract mode.
- **`DetailedNodePerformanceV2` gains two optional fields:** the figure's source epoch (contract mode) and when it was taken (the snapshot's block time in contract mode, the refresh time in legacy mode). Additive, on a JSON/YAML-only route; the V1 types are unchanged.
- **Startup waits for its caches.** nym-api builds the mixnet contract, describe, node families and annotation caches first, and only then spawns its other tasks and the HTTP server. The annotation cache loses its empty-map placeholder, its refresher no longer waits for the describe cache's first full pass or for its own 305 s rate limit before the first refresh, and a failed first build is retried every 30 s. The signers cache refresher moves after the wait, since it probes this nym-api's own HTTP.
- **HTTP attestation source for performance** in `nym-performance-client` (`AttestationSource` with `Record = LatestPerformance`), with its `NymApiClientExt` methods beside the directory's, so an `AttestedTrustAnchor` can reach quorum over nym-api producers.
- **No read flag.** `[performance_provider].read_performance_contract`, added by `nym-api-performance-contract-consumer` and never released, is removed: every nym-api reads the contract for its snapshots. The window is now held only by a nym-api with `[rewarding].enabled`, which serves contract-mode rewarding and selection and, with the switch off, the `contract-divergence` route; elsewhere that route answers 503. The switch requires nothing any more. The window's startup rule (load with a submission or fail) applies to that nym-api only. A config that still sets the flag loads, the value ignored.
- **The contract-mode rewarding and selection rules move onto the window**, as methods beside the figure they read, so the whole rewarding view sits in one module that lifts out of nym-api later.

## Capabilities

### New Capabilities

- `performance-attestation-provider`: nym-api's producer of attested performance snapshots: always on, the directory's cadence and retained window, producing only what `PerformanceClient` verified, the `/v1/performance` route tree, the unproven medians and weights read beside each snapshot, and the persisted snapshot cache.
- `nym-api-startup`: nym-api builds its startup caches before spawning its tasks and HTTP server, retries a failed first build every 30 s, and serves no placeholder value from a cache it has not built.

### Modified Capabilities

- `directory-attestation-provider`: the settle-lagged-latest requirement names the setting that decides it and that every attested contract shares it, with a scenario pinning the fix; the whole-directory serving requirement says its node-identity route serves the identity map for every contract attested at that height.
- `performance-retrieval-client`: a new requirement for the HTTP attestation source over nym-api's `/v1/performance` routes, taking the identity map from the directory tree.
- `nym-network-monitor`: the read-flag requirement is renamed and rewritten (no flag; every nym-api reads the contract; the window only where rewarding is enabled; the startup rule narrowed to that nym-api); the window and `contract-divergence` requirements lose the flag; the consumer-surface requirement's contract-mode paragraph and scenario say what contract mode now publishes, and `liveness-divergence` answers 503 in contract mode; new requirements cover contract-mode annotations from the verified routing figure and the two new annotation fields.
- `network-monitor`: the route-selection feedback-loop consumer says contract mode has no annotations, so every candidate takes the preparer's default weight. With this change it is weighted by the contract's routing figure.

## Impact

**Code:**
- `nym-api/src/directory/`, `support/http/state/directory.rs`: onto the generic snapshot machinery (new module under `nym-api/src/support/`), `ParsedDirectory` dropped, the settle lag fixed in `support/cli/run.rs`.
- New performance producer, state and `/v1/performance` handlers in nym-api; mounted in `support/http/router.rs`; `AppState` gains the performance state.
- `nym-api/src/node_status_api/cache/`: the contract-mode annotation builder reading the performance snapshot cache; the placeholder removed; the readiness check and the first refresh.
- `nym-api/src/support/caching/refresher.rs`: the 30 s first-build retry.
- `nym-api/src/support/cli/run.rs`: the startup order around the cache wait, the flag removed, the window gated by `[rewarding].enabled`, the signers refresher after the wait.
- `nym-api/src/node_performance/contract_window/`: the rewarding and selection rules as methods; `epoch_operations` calls them.
- `nym-api/src/unstable_routes/v3/nym_nodes/`: the two divergence routes' 503s.
- `nym-api/src/support/config`: the flag removed, docs, the template.
- `nym-api/nym-api-requests`: the two `DetailedNodePerformanceV2` fields (TS bindings regenerated), the `/v1/performance` records response.
- `common/client-libs/validator-client`: `NymApiClientExt` performance methods; height-pinned reads for the weights, the last submission and an epoch's medians on `PinnedPerformanceQueryClient`.
- `common/nym-performance-client`: the HTTP attestation source.
- `common/cosmwasm-smart-contracts/nym-performance-contract`: an optional `utoipa` feature so `LatestPerformance` appears in nym-api's OpenAPI document. No contract code change.

**APIs:** three new routes under `/v1/performance`; two optional fields on `DetailedNodePerformanceV2` (served directly only by `/v2/nym-nodes/annotation/{node_id}`, JSON/YAML); the directory's latest snapshot promoted after `settle_lag` blocks; in contract mode, the annotation routes' sub-scores come from the contract and `liveness-divergence` answers 503; at startup nym-api serves nothing until its caches are built. No contract, message or database change.

**Deployment:** every nym-api reads the performance contract from this release on, so its address must be in the network details everywhere (the mainnet constant, empty today, ships with the release; environments without the contract fail startup). Startup takes seconds longer on a restart and, on a fresh install or after more than 75 minutes down, waits for the describe pass and the first annotation refresh before serving anything, ecash routes included. The persisted annotation cache changes shape with the new fields, so its file is renamed; the upgrade restart waits for the first annotation refresh rather than serving zeros. The switch stays off until this change and the orchestrator's aliveness follow-up are deployed.
