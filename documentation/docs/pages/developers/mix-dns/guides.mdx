# Reference & security

## Configuration

The DNS resolver is configured at tunnel setup, not per-call. Pass the resolver in `setupMixTunnel`:

```ts
await setupMixTunnel({
  // Set the DoH resolvers explicitly, tried in order. Each is an HTTPS DoH
  // endpoint URL. Defaults are Quad9, Cloudflare, and Google.
  dohEndpoints: ['https://9.9.9.9/dns-query', 'https://1.1.1.1/dns-query'],
});
```

The full options surface is documented under [`SetupMixTunnelOpts`](/developers/mix-tunnel/api/interfaces/SetupMixTunnelOpts).

## Security model

`mix-dns` follows the shared [mixnet exit security model](/network/infrastructure/exit-services). The transport-specific exposure: at the IPR exit the query leaves as a DNS-over-HTTPS request (TCP plus TLS) to the resolver, so the resolver sees the queried hostname and the IPR's IP, never yours. Unlike plain UDP DNS, the query and response are encrypted on the IPR-to-resolver leg, so an on-path observer between the exit and the resolver cannot read the hostname.

<Callout type="warning">
DoH encrypts the query in transit, but the resolver still decrypts and answers it, so it reads the hostname you are looking up, while the mixnet keeps it from learning who you are. Choosing one DoH endpoint over another only changes which third party sees the queries; all of them see them coming from the IPR. To remove the resolver from your trust set, pick one you already trust.
</Callout>
