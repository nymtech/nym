# node-status-api-http Specification

> Generated by openlore on 2026-07-07

## Purpose

Defines the public read HTTP API of the node status service: an axum server that serves gateway, mixnode, nym-node, dVPN directory, services, summary, metrics, and status data. Read endpoints are served from an in-memory cache backed by PostgreSQL, with OpenAPI/Swagger documentation. (The authenticated `/internal/testruns` endpoints are specified in [[node-status-api-testruns]].)

## Requirements

### Requirement: The API SHALL serve read endpoints from a TTL cache backed by the database

Read-heavy list endpoints (gateways, dVPN gateways, gateway IPs, nym-nodes, mixnode stats, summary history, session stats) MUST be served from per-list `moka` caches with capacity 1 and TTL = the configured `nym_http_cache_ttl` (default 30s). On a cache miss the value MUST be rebuilt from the database and cached. Pagination MUST default to size 10 (max 200) and page 0, returning a `PagedResult { page, size, total, items }`.

#### Scenario: Cache hit within TTL
- **GIVEN** a cached gateway list within its TTL
- **WHEN** `GET /v2/gateways` is called
- **THEN** the cached list is paginated and returned without hitting the database

#### Scenario: Cache miss rebuilds from DB
- **GIVEN** an expired or empty gateway cache
- **WHEN** `GET /v2/gateways` is called
- **THEN** the list is loaded from the database, cached, and returned

### Requirement: The API SHALL expose the documented set of public read routes

The router MUST serve (all unauthenticated, open CORS): `GET /` (redirect to `/swagger`); Swagger UI and `GET /api-docs/openapi.json`; `GET /v2/gateways`, `/v2/gateways/skinny`, `/v2/gateways/{identity_key}`; `GET /v2/mixnodes/stats`; `GET /v2/services`; `GET /v2/summary`, `/v2/summary/history`; `GET /v2/metrics/sessions`; `GET /v2/status/build_information`, `/v2/status/health`; `GET /explorer/v3/nym-nodes`, `/explorer/v3/nym-nodes/{node_id}/delegations`; and the `GET /dvpn/v1/directory/gateways*` family (all, ips, countries, by country, and entry/exit variants). CORS MUST allow any origin with methods `POST/GET/PATCH/OPTIONS` and credentials disabled.

#### Scenario: Single gateway lookup miss
- **WHEN** `GET /v2/gateways/{identity_key}` is called with an unknown identity
- **THEN** the response is HTTP 400 (invalid input)

#### Scenario: Delegations for a node with none
- **WHEN** `GET /explorer/v3/nym-nodes/{node_id}/delegations` is called for a node with no delegations
- **THEN** the response is HTTP 404

#### Scenario: Root redirects to Swagger
- **WHEN** `GET /` is called
- **THEN** the response redirects to `/swagger`

### Requirement: The dVPN directory SHALL filter, enrich, and classify gateways

The dVPN gateway list MUST include only gateways that are bonded, have performance > 0, are present in the nym-nodes table, and carry a valid 2-letter country; it MUST be enriched with family and stake information and a SOCKS5 percentile score, and sorted by (country, identity key). A read-time version filter MUST apply (default minimum node version 1.6.2). Entry gateways MUST be those whose last probe `can_route_entry`; exit gateways MUST be those whose last probe can route external IPv4 **and** IPv6.

#### Scenario: Entry directory filters by probe capability and version
- **WHEN** `GET /dvpn/v1/directory/gateways/entry` is called
- **THEN** only gateways whose last probe indicates entry routing and whose version ≥ the minimum are returned, sorted by country

#### Scenario: Exit requires dual-stack routing
- **GIVEN** a gateway whose last probe can route external IPv4 but not IPv6
- **WHEN** the exit directory is built
- **THEN** that gateway is excluded from the exit list

### Requirement: The API SHALL derive services from gateway self-described JSON via JSONPath

The `/v2/services` endpoint MUST derive each service's IP, hostname, and service-provider client id from the gateway `self_described` JSON using JSONPath expressions (host IP, hostname, network-requester address). The default filter MUST keep only gateways that advertise a network-requester service provider; `entry=true` MUST keep all; `wss` and `hostname` filters MUST further restrict the set.

#### Scenario: Default services filter
- **WHEN** `GET /v2/services` is called with no filters
- **THEN** only gateways advertising a network-requester service provider are returned

### Requirement: Probe results SHALL deserialize with schema fallback and be scored for display

Stored probe results MUST deserialize by first attempting the latest `nym_gateway_probe` format, then falling back to the crate's older schema, back-filling WireGuard v4 fields into generic fields for compatibility. The API MUST compute a visual gateway score weighting mixnet 40% / download-speed 30% / ping 30% into `Offline|Low|Medium|High`, and bucket gateways into SOCKS5 percentile scores by HTTPS latency (latency 0 → Offline; lowest 50% → High, next 25% → Medium, worst 25% → Low).

#### Scenario: Backward-compatible probe deserialization
- **GIVEN** a stored probe result in the older schema
- **WHEN** the API reads it
- **THEN** it falls back to the legacy format and back-fills WG v4 fields rather than failing

#### Scenario: Zero-latency SOCKS5 scores Offline
- **GIVEN** a gateway whose SOCKS5 HTTPS latency is 0
- **WHEN** the percentile score is computed
- **THEN** the gateway is scored Offline

### Requirement: The API SHALL map error conditions to typed HTTP statuses

Errors MUST map as: invalid input → 400, unauthorized → 401, "no testruns available" → 503, "no delegations for node" → 404, and internal errors → 500 (with optional logging). Summary reads MUST require all summary keys to be present, returning 500 otherwise.

#### Scenario: No testruns available
- **WHEN** an internal testrun request finds nothing to assign
- **THEN** the API returns HTTP 503

## Technical Notes

- **Implementation**: `http/server.rs` (`start_http_api`, binds `0.0.0.0:{http_port}`), `http/api/mod.rs` (router + CORS + request logging), `http/state.rs` (`AppState`, `HttpCache`), `http/models/mod.rs` (`Gateway`, `DVpnGateway`, `ExtendedNymNode`, `Service`, `SessionStats`, scoring), `http/models/gw_probe/` (probe deserialization + scoring + `socks5_calc.rs`), `http/error.rs`.
- **Known behavior**: `get_gateway_list` panics if the gateways table read fails (treated as unrecoverable).
- **Framework**: axum + tower-http; OpenAPI via utoipa/utoipa-swagger-ui/utoipauto.
- **Related specs**: reads persisted data from [[node-status-api-persistence]]; enriched by [[node-status-api-monitoring]]; probe result shapes come from [[gateway-probe]].
