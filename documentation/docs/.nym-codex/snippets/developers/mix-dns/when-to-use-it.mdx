## When to use it [#when-to-use-it]

`mix-dns` is for cases where you need the resolved IP itself, not a connection that uses it. [`mix-fetch`](snippet:nym/developers/mix-fetch/intro) and [`mix-websocket`](snippet:nym/developers/mix-websocket/intro) already resolve via the mixnet internally; you don't need to call `mixDNS` before either.

Direct uses:

- Validate that a hostname resolves to an expected IP range before connecting through any path.
- Build IP-based allow / deny lists for an app that performs the connection itself.
- Probe whether a hostname is reachable from the IPR exit's perspective without opening a connection.
