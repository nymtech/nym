## Purpose

Describes the runtime structure, process model, and cross-component contracts of the node-status subsystem: how the API process is composed of an HTTP server plus background workers, how the agent runs as a looped one-shot CLI, and how the probe is embedded as a library versus run as a binary.

## Requirements

### Requirement: The node status API SHALL run as a single process hosting an HTTP server and multiple background workers

On startup the service MUST set up tracing, parse CLI/env configuration, initialise the PostgreSQL pool and run migrations, build shared caches, connect a `nyxd` client, and then spawn its background workers under a `nym_task` shutdown manager before starting the axum HTTP server and running until shutdown.

The workers spawned MUST include: the description scraper, the packet-stats node scraper, the network monitor, the test-run queuer, the metrics scraper, and the ticketbook manager (with its quorum-state checker). A `ScrapeNode { node_id }` subcommand MUST instead perform a single node scrape and exit.

#### Scenario: Default startup spawns the full worker set and HTTP server
- **GIVEN** valid configuration and a reachable database
- **WHEN** the service is started with no subcommand
- **THEN** it runs migrations, spawns the monitor, both scrapers, the test-run queuer, the metrics scraper, and the ticketbook manager, and binds the HTTP API on `0.0.0.0:{http_port}` (default 8000)

#### Scenario: One-shot node scrape subcommand
- **WHEN** the service is invoked as `ScrapeNode { node_id }`
- **THEN** it scrapes that single node's description and exits without spawning the long-running workers or HTTP server

### Requirement: Background workers SHALL use independent timed loops with per-loop failure retry

Each background worker MUST run its own `tokio` timed loop rather than a shared scheduler. On a failed cycle a worker MUST sleep a short retry delay (e.g. 60s for the monitor and metrics scraper) and retry; on success it MUST sleep its configured refresh interval. All loops MUST honour graceful shutdown via the shutdown manager.

#### Scenario: Monitor retries after a failed cycle
- **GIVEN** the network monitor loop
- **WHEN** a monitor cycle returns an error
- **THEN** the loop sleeps the failure-retry delay (60s) and retries, rather than aborting the process

### Requirement: The agent SHALL run as a one-shot CLI, looped externally

The agent process MUST parse its arguments once, execute a single subcommand, and exit. Continuous operation is currently achieved by an external loop (the container `entrypoint.sh` runs it in a `while true` loop with a `SLEEP_TIME` interval), and the agent as built implements no daemon loop and no retry across invocations. That is a description of the current deployment shape rather than a constraint on future ones: nothing in the API contract requires one-shot execution, so a replacement MAY run as a long-lived process provided each cycle still requests, probes and submits independently.

#### Scenario: Agent exits after one subcommand
- **WHEN** the agent is invoked with `run-probe`
- **THEN** it executes exactly one probe cycle (request → run → submit) and exits, relying on the external loop to schedule the next run

### Requirement: The gateway probe SHALL be usable both as an embedded library and as a standalone binary

The probe MUST expose a `Probe` API that the agent links and calls in-process (`Probe::new_for_agent`, `probe_run_agent`, `run_ports_for_agent`) — it is NOT spawned as a subprocess by the agent. The same crate MUST also provide a standalone CLI binary that prints results as JSON to stdout. The binary MUST only build/run on Unix; on non-Unix targets it MUST exit with an error.

#### Scenario: Agent uses the probe as a library
- **WHEN** the agent executes an assigned test run
- **THEN** it calls the `nym-gateway-probe` library functions directly in-process rather than launching the probe binary

## Technical Notes

- **Implementation**: `nym-node-status-api/.../main.rs`, `.../http/server.rs`, `.../http/state.rs` (`AppState`), `nym-gateway-probe/src/main.rs`, `nym-node-status-agent/src/main.rs`
- **Web framework**: axum + tower-http (CORS, tracing); OpenAPI via utoipa/utoipa-swagger-ui/utoipauto.
- **Persistence**: PostgreSQL via `sqlx` (compile-time checked queries, migrations in `./migrations_pg`); in-memory read caching via `moka`.
- **Concurrency**: `tokio` multi-thread runtime; graceful shutdown via `nym_task::ShutdownManager`; DB claims made concurrency-safe with `FOR UPDATE ... SKIP LOCKED`.
