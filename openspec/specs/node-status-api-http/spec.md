# node-status-api-http Specification

> Generated by openlore on 2026-07-07
> Revised 2026-08-03: reverse-engineered from the implementation to capture the exact wire contract of every endpoint (statuses, bodies, field names, quirks), because any replacement of this API must be byte-for-byte compatible for existing consumers (NymVPN clients, the dVPN/VPN API, explorer front-ends, and the node-status agents).
> Source files: `nym-node-status-api/nym-node-status-api/src/http/{mod,server,state,error,api_docs}.rs`, `http/api/{mod,gateways,mixnodes,nym_nodes,summary,status,testruns,services/*,metrics/*,dvpn/*}.rs`, `http/models/{mod,gw_probe/*}.rs`, `db/{models}.rs`, `db/queries/{gateways,nym_nodes,summary}.rs`, `monitor/geodata.rs`, `cli/mod.rs`, `nym-node-status-client/src/{lib,api,models,auth}.rs`

## Purpose

Defines the HTTP surface of the node status service: an axum 0.8 server that serves gateway, mixnode, nym-node, dVPN directory, services, summary, metrics and status data from in-memory caches over PostgreSQL, plus the authenticated `/internal/testruns` agent endpoints. This spec is the compatibility contract: it fixes route paths, status codes, content types, response envelopes, field names and the known behavioural quirks that consumers depend on. Test-run orchestration semantics behind the internal endpoints are specified in [[node-status-api-testruns]].

## Requirements

### Requirement: The API SHALL serve exactly this route table

The server MUST bind `0.0.0.0:{http_port}` (default 8000) and serve the following routes and no others. All `/v2`, `/explorer/v3` and `/dvpn/v1` routes MUST be unauthenticated; only `/internal/testruns*` requires agent authentication. Nested routers register their root handler such that the bare path (no trailing slash) is served, e.g. `GET /v2/gateways` and `GET /internal/testruns`.

#### Scenario: Root redirects permanently to Swagger

- **WHEN** `GET /` is called
- **THEN** the response is 308 Permanent Redirect with `Location: /swagger` and an empty body

#### Scenario: Unknown path

- **WHEN** a path outside the table is requested
- **THEN** axum's fallback returns 404 with an empty body (no JSON error envelope)

#### Scenario: Method not allowed on a known path

- **WHEN** `POST /v2/gateways` is called
- **THEN** the response is 405 Method Not Allowed with an empty body

#### Scenario: Cross-origin read from a browser

- **GIVEN** a browser on any origin
- **WHEN** it issues a preflight and then `GET /v2/summary`
- **THEN** the response carries `access-control-allow-origin: *` and no credentials are allowed

### Requirement: Successful responses SHALL be bare serde-serialized JSON with no envelope

Every data endpoint (everything except `/`, `/swagger*` and the empty 201s) MUST answer with `Content-Type: application/json` and a body produced by `serde_json` directly from the response model, with no wrapper object, no `data`/`result` key, and no status field. Field names MUST be exactly the Rust field names (no case conversion, except where a nested external type declares its own `rename_all`). Optional fields MUST be emitted as explicit `null` (no field is skipped when empty). Numeric conventions MUST be: `u8`/`u16`/`u32`/`u64`/`i32`/`i64`/`u128` as JSON numbers, `cosmwasm_std::Decimal` and `Uint128` as JSON strings, `IpAddr` as a string, `time::Date` as `YYYY-MM-DD`, unix timestamps converted to RFC3339 UTC with `Z` and second precision (e.g. `2026-07-07T14:05:48Z`), and `ed25519`/`x25519` keys as base58 strings except inside agent request payloads (see [[node-status-api-testruns]]).

#### Scenario: Absent optional value

- **GIVEN** a gateway with no stored probe result
- **WHEN** `GET /v2/gateways` returns it
- **THEN** the item contains `"last_probe_result": null` rather than omitting the key

#### Scenario: Timestamp rendering

- **GIVEN** a gateway whose `last_updated_utc` column holds the unix timestamp 1672531199
- **WHEN** it is serialized
- **THEN** the field value is the string `"2022-12-31T23:59:59Z"`

### Requirement: Paged endpoints SHALL return the PagedResult envelope with these exact pagination semantics

`/v2/gateways`, `/v2/gateways/skinny`, `/v2/services`, `/v2/metrics/sessions` and `/explorer/v3/nym-nodes` MUST return `{ "page": usize, "size": usize, "total": usize, "items": [...] }` where `total` is the length of the full (post-filter, pre-pagination) list and `items` is the `page`-th chunk of `size` elements. Query parameters MUST be `size` and `page`; `size` defaults to 10 and is silently clamped to a maximum of 200; `page` defaults to 0 and is 0-indexed. When `page * size > total` the served page MUST be recomputed as `total / size` (integer division) and the recomputed value MUST be reported in the `page` field. Non-numeric `size`/`page` MUST be rejected by the query extractor with 400. Unknown query parameters MUST be ignored. Note the cost this imposes on whole-list consumers: a client that does not pass `size` walks the full gateway list 10 items at a time (roughly 70 requests, each with its own TLS handshake), and the 200 cap means even a deliberate caller needs several round trips. The dVPN directory routes are the exception - they are unpaginated and return the whole array in one response.

#### Scenario: Defaults applied

- **WHEN** `GET /v2/gateways` is called with no query parameters
- **THEN** the response has `"page": 0`, `"size": 10` and at most 10 items

#### Scenario: Size clamped silently

- **WHEN** `GET /v2/gateways?size=1000` is called
- **THEN** the response reports `"size": 200` and returns at most 200 items, without an error

#### Scenario: Out-of-range page snaps back

- **GIVEN** 15 items in the list
- **WHEN** `GET /v2/gateways?size=10&page=10` is called
- **THEN** the response is `page=1, size=10, total=15` with the final 5 items

#### Scenario: Exact-boundary page returns an empty page

- **GIVEN** exactly 20 items in the list
- **WHEN** `GET /v2/gateways?size=10&page=2` is called
- **THEN** the response is `page=2, size=10, total=20, items=[]` (the clamp does not trigger because `page * size` is not strictly greater than `total`)

#### Scenario: Zero page size aborts the request

- **WHEN** any paged endpoint is called with `size=0`
- **THEN** the handler panics on a zero-length chunk, the connection is aborted with no HTTP response, and the process keeps serving other connections

### Requirement: Error responses SHALL be plain-text bodies with these exact statuses and messages

All errors raised by handlers MUST be rendered as `(status, message)` - i.e. `Content-Type: text/plain; charset=utf-8` with the bare message as the body and no JSON envelope. The mapping MUST be:

| Condition | Status | Body |
| --- | --- | --- |
| invalid input | 400 | the offending value or a specific message, echoed verbatim |
| unregistered agent key or bad signature or stale request | 401 | `Make sure your public key is registered with NS API` |
| no delegation data for node | 404 | `No delegation data for node_id={node_id}` |
| internal failure | 500 | `Internal server error` |
| no test run available to assign | 503 | `No testruns available` |

The 503 body MUST remain exactly `No testruns available`: the agent client matches on that substring to distinguish "nothing to do" from a real failure, and any other 5xx body makes agents treat the poll as an error. Extractor-level rejections MUST be axum's own plain-text rejections and are not remapped: 400 for undeserializable path/query parameters, 400 for malformed JSON syntax, 415 for a missing or wrong `Content-Type` on a JSON body, 422 for well-formed JSON that does not match the target type, and 413 when a body exceeds the limit. The single exception MUST be `POST /internal/testruns/{id}` (v1), which captures the JSON rejection itself and re-emits every variant as 400 with the rejection text as the body, so a wrong content type or a schema mismatch there yields 400 where the v2 endpoints yield 415 or 422 (see [[node-status-api-testruns]]).

#### Scenario: Unknown gateway echoes the key

- **WHEN** `GET /v2/gateways/NOT_A_REAL_KEY` is called
- **THEN** the response is 400 with `Content-Type: text/plain; charset=utf-8` and the body `NOT_A_REAL_KEY`

#### Scenario: Agent poll with nothing queued

- **GIVEN** no queued test run
- **WHEN** an authenticated agent requests one
- **THEN** the response is 503 with the exact body `No testruns available`

#### Scenario: Internal error hides detail

- **GIVEN** an aggregation failure while building the nym-nodes list
- **WHEN** `GET /explorer/v3/nym-nodes` is called
- **THEN** the response is 500 with the body `Internal server error` and the cause is only logged

### Requirement: The gateway endpoints SHALL return the stored gateway record verbatim, with hardcoded scores

`GET /v2/gateways` and `GET /v2/gateways/{identity_key}` MUST return `Gateway` items with exactly these fields:

```json
{
  "gateway_identity_key": "<base58 ed25519>",
  "bonded": true,
  "performance": 95,
  "self_described": { },              // raw stored self-description JSON, or null
  "explorer_pretty_bond": { },        // { identity_key, owner, pledge_amount: {denom, amount}, location: {...} }, or null
  "description": { "moniker": "", "website": "", "security_contact": "", "details": "" },
  "last_probe_result": { },           // raw stored probe JSON, or null
  "last_probe_log": "",               // or null
  "ports_check": { },                 // normalised summary, or null
  "last_ports_check_utc": "",         // RFC3339, or null
  "last_testrun_utc": "",             // RFC3339, or null
  "last_updated_utc": "",             // RFC3339, never null
  "routing_score": 0.0,
  "config_score": 0,
  "bridges": { }                      // or null
}
```

`routing_score` MUST be `0.0` and `config_score` MUST be `0` for every gateway: both are hardcoded in the DTO conversion and no longer reflect any measurement (the underlying columns are dead too - nothing writes them, see [[node-status-api-persistence]]). Missing description columns MUST be served as the literal string `NA` for `moniker`, `website`, `security_contact` and `details`. `self_described`, `explorer_pretty_bond` and `last_probe_result` MUST be re-emitted structurally rather than byte-for-byte: the stored text is parsed into a JSON value and re-serialized, so object keys come out **alphabetically sorted at every level** and original key order and whitespace are lost. Each MUST become `null` when the stored text is absent, is the JSON literal `null`, or fails to parse - malformed stored JSON is silently collapsed to `null` rather than surfaced as text or an error. The same applies to the `ports_check` and `bridges` values, which additionally pass through Postgres JSONB normalisation on write. `ports_check` MUST be normalised to `{ "all_pass": bool, "error": string|null, "port_check_target": string|null, "failed_ports": [string] }`, converting the legacy `{ can_register, port_check_target, ports, error }` shape on read. Items MUST be ordered by `gateway_identity_key` ascending (the DB read order). Gateway rows that fail DTO conversion MUST be skipped rather than failing the request.

`GET /v2/gateways/skinny` MUST return only `bonded` gateways, and each `GatewaySkinny` item MUST contain exactly `gateway_identity_key`, `self_described`, `explorer_pretty_bond`, `last_probe_result`, `ports_check`, `last_ports_check_utc`, `last_testrun_utc`, `last_updated_utc`, `routing_score`, `config_score`, `performance` - i.e. it MUST drop `bonded`, `description`, `last_probe_log` and `bridges`.

`GET /v2/gateways/{identity_key}` MUST match on exact string equality against `gateway_identity_key` and MUST return 400 (not 404) when there is no match.

#### Scenario: Unbonded gateway visible on the full list only

- **GIVEN** a gateway row with `bonded=false`
- **WHEN** `GET /v2/gateways` and `GET /v2/gateways/skinny` are called
- **THEN** it appears in the former with `"bonded": false` and is absent from the latter

#### Scenario: Legacy ports-check payload normalised

- **GIVEN** a gateway whose stored `ports_check` uses the legacy `{ can_register, port_check_target, ports, error }` shape
- **WHEN** the gateway is served
- **THEN** the response contains the four-key `{ all_pass, error, port_check_target, failed_ports }` form, with `failed_ports` listing the ports whose value is `false`

#### Scenario: Scores are not measurements

- **WHEN** any gateway is served
- **THEN** `routing_score` is `0.0` and `config_score` is `0` regardless of probe history

#### Scenario: Malformed stored JSON collapses to null

- **GIVEN** a gateway whose stored `last_probe_result` text is truncated and no longer parses
- **WHEN** the gateway is served
- **THEN** `last_probe_result` is `null` and the request still succeeds

#### Scenario: Key order is not preserved

- **GIVEN** a gateway whose stored `self_described` text lists `zebra` before `alpha`
- **WHEN** the gateway is served
- **THEN** the response object lists `alpha` before `zebra`, so consumers MUST NOT depend on stored key order or on hashing the raw bytes

### Requirement: `/v2/mixnodes/stats` SHALL return up to 30 ascending daily rows with an offset window

`GET /v2/mixnodes/stats` MUST return a bare JSON array of `{ "date_utc": "YYYY-MM-DD", "total_packets_received": i64, "total_packets_sent": i64, "total_packets_dropped": i64, "total_stake": i64 }`, aggregated per day across all nodes. `date_utc` MUST be a zero-padded `YYYY-MM-DD` string (it is stored as text and ordered lexicographically, which coincides with chronological order for that format). The rows MUST be ordered oldest-first. The optional `offset` query parameter MUST shift the window back by that many days from the newest available day, keeping at most 30 rows (`offset` counts days, not rows dropped from the response). A negative `offset` MUST be rejected with 400 and the body `Offset must be non-negative`. A database failure MUST yield an empty array with status 200, not a 500.

#### Scenario: Default window

- **GIVEN** 45 days of stored daily stats
- **WHEN** `GET /v2/mixnodes/stats` is called
- **THEN** the 30 most recent days are returned, oldest-first

#### Scenario: Offset window

- **GIVEN** 45 days of stored daily stats
- **WHEN** `GET /v2/mixnodes/stats?offset=5` is called
- **THEN** the 5 most recent days are excluded and the 30 days preceding them are returned, oldest-first

#### Scenario: Negative offset

- **WHEN** `GET /v2/mixnodes/stats?offset=-1` is called
- **THEN** the response is 400 with the body `Offset must be non-negative`

#### Scenario: Query failure degrades to empty

- **GIVEN** the daily-stats query fails
- **WHEN** the endpoint is called
- **THEN** the response is 200 with `[]` and the error is only logged

### Requirement: `/v2/services` SHALL derive service entries via JSONPath and report a constant routing score

`GET /v2/services` MUST build one candidate entry per gateway in the cached gateway list, extracting from the gateway's `self_described` JSON via exactly these JSONPath expressions: `$.host_information.ip_address[0]` for `ip_address`, `$.host_information.hostname` for `hostname`, `$.network_requester.address` for `service_provider_client_id`. Each extraction MUST yield `null` unless the path matches exactly one string value. Items MUST have exactly these fields:

```json
{
  "gateway_identity_key": "",
  "last_updated_utc": "",             // gateway.last_updated_utc, RFC3339
  "routing_score": 1.0,               // constant
  "service_provider_client_id": "",   // or null
  "ip_address": "",                   // or null
  "hostname": "",                     // or null
  "mixnet_websockets": { },           // self_described.mixnet_websockets passthrough, or null
  "last_successful_ping_utc": ""      // gateway.last_testrun_utc, or null
}
```

`routing_score` MUST be the constant `1.0`. Filtering MUST be: keep only entries with a non-empty `service_provider_client_id` by default; `entry=true` MUST set the initial keep to true for all entries (so gateways without a network requester are included); `wss=true` MUST additionally require `mixnet_websockets.wss_port` to be present and non-null (a value of `0` counts as present); `hostname=true` MUST additionally require a non-null `hostname`. `wss`/`hostname` MUST still be able to exclude entries when `entry=true`. Pagination MUST use this endpoint's own `size`/`page` parameters with the shared `PagedResult` semantics. A JSONPath compilation failure MUST return 500.

#### Scenario: Default filter keeps only network requesters

- **GIVEN** four gateways, two of which advertise `network_requester.address`
- **WHEN** `GET /v2/services` is called
- **THEN** only those two are returned

#### Scenario: Entry mode plus wss filter

- **GIVEN** gateways with and without `mixnet_websockets.wss_port`
- **WHEN** `GET /v2/services?entry=true&wss=true` is called
- **THEN** all gateways with a `wss_port` are returned regardless of network-requester support, and those without are excluded

### Requirement: `/v2/summary` SHALL return a complete NetworkSummary or 500

`GET /v2/summary` MUST read the `summary` key-value table directly (it is NOT cached) and MUST return:

```json
{
  "total_nodes": 0,
  "mixnodes": {
    "bonded":     { "count": 0, "self_described": 0, "last_updated_utc": "" },
    "historical": { "count": 0, "last_updated_utc": "" }
  },
  "gateways": {
    "bonded":     { "count": 0, "entry": 0, "exit": 0, "last_updated_utc": "" },
    "historical": { "count": 0, "last_updated_utc": "" }
  }
}
```

All eight keys `nymnode.total.count`, `assigned.mixing.count`, `nymnode.described.count`, `gateways.bonded.count`, `assigned.entry.count`, `assigned.exit.count`, `mixnodes.historical.count`, `gateways.historical.count` MUST be present; if any is missing the endpoint MUST return 500 rather than a partial summary. Counts MUST be parsed from the stored text as `i32`, falling back to `0` on a parse failure. Each `last_updated_utc` MUST be the RFC3339 rendering of the source row's own `last_updated_utc`: the mixnode `bonded` block takes it from `assigned.mixing.count`, the gateway `bonded` block from `gateways.bonded.count`, and each `historical` block from its own key.

#### Scenario: Missing summary key

- **GIVEN** the `summary` table lacks `assigned.exit.count`
- **WHEN** `GET /v2/summary` is called
- **THEN** the response is 500 with the body `Internal server error`

#### Scenario: Unparsable count

- **GIVEN** a summary row whose `value_json` is not an integer
- **WHEN** the summary is served
- **THEN** the corresponding count is `0` and the request still succeeds

### Requirement: `/v2/summary/history` SHALL return the 30 most recent daily snapshots newest-first

`GET /v2/summary/history` MUST return a bare array of `{ "date": "YYYY-MM-DD", "value_json": <any JSON>, "timestamp_utc": "<RFC3339>" }`, ordered by `date` descending (lexicographic order over the stored `YYYY-MM-DD` text) and limited to 30 rows. `value_json` MUST be the stored daily snapshot parsed back into JSON - in practice a whole `NetworkSummary` object as written by the monitor, one row per UTC day refreshed until midnight - or `null` when the stored text does not parse. A query failure MUST yield `[]` with status 200.

#### Scenario: Newest first

- **GIVEN** 45 stored history rows
- **WHEN** the endpoint is called
- **THEN** 30 rows are returned with the most recent date first

### Requirement: `/v2/metrics/sessions` SHALL page over cached session stats with day and node filters

`GET /v2/metrics/sessions` MUST return `PagedResult<SessionStats>` where each item is:

```json
{
  "gateway_identity_key": "",
  "node_id": 0,
  "day": "YYYY-MM-DD",
  "unique_active_clients": 0,
  "session_started": 0,
  "users_hashes": null,
  "vpn_sessions": null,
  "mixnet_sessions": null,
  "unknown_sessions": null
}
```

The `day` query parameter MUST be parsed as an ISO-8601 date and filter on exact equality; an unparsable value MUST return 400 with the offending string echoed as the body. The `node_id` query parameter MUST be parsed as `u32` and filter on equality; an unparsable value MUST return 400 with the offending string echoed. Filtering MUST be applied before pagination so that `total` reflects the filtered set. A query failure MUST be served as an empty list, not a 500. The underlying query imposes no `ORDER BY`, so item order is unspecified and pagination is not stable across cache refills (see [[node-status-api-persistence]]).

#### Scenario: Filter by day and node

- **WHEN** `GET /v2/metrics/sessions?day=2026-07-01&node_id=42` is called
- **THEN** only records for node 42 on that day are returned and `total` counts only those

#### Scenario: Bad day value

- **WHEN** `GET /v2/metrics/sessions?day=yesterday` is called
- **THEN** the response is 400 with the body `yesterday`

### Requirement: `/v2/status/*` SHALL expose build information and process uptime

`GET /v2/status/build_information` MUST return the binary's compile-time build info with exactly the fields `binary_name`, `build_timestamp`, `build_version`, `commit_sha`, `commit_timestamp`, `commit_branch`, `rustc_version`, `rustc_channel`, `cargo_profile`, `cargo_triple`. `GET /v2/status/health` MUST return exactly `{ "uptime": <whole seconds since process start> }` with status 200 - there MUST be no other field, and the endpoint MUST NOT check database or upstream health (it is a liveness signal only).

#### Scenario: Health while the database is down

- **GIVEN** the database is unreachable
- **WHEN** `GET /v2/status/health` is called
- **THEN** the response is still 200 with a positive `uptime`

### Requirement: `/explorer/v3/nym-nodes` SHALL return described nodes enriched with stake, geo and family data

`GET /explorer/v3/nym-nodes` MUST return `PagedResult<ExtendedNymNode>` built from the set of nodes that have a stored self-description (nodes without one MUST be absent), with exactly these fields:

```json
{
  "node_id": 0,
  "identity_key": "<base58 ed25519>",
  "uptime": 0.0,                      // nym-api performance as f64 0..1, 0.0 when unknown
  "total_stake": "0",                 // Decimal as string, "0" when unbonded
  "original_pledge": 0,               // u128 number, 0 when unbonded
  "bonding_address": null,            // owner address, null when unbonded
  "bonded": false,                    // true iff bond info is present
  "node_type": "nym_node",            // legacy_mixnode | legacy_gateway | nym_node
  "ip_address": "",                   // first declared host IP, "" when none
  "accepted_tnc": false,
  "self_description": { },            // full stored self-description (NymNodeDataV2 shape)
  "rewarding_details": { },           // mixnet-contract NodeRewarding, or null when unbonded
  "description": { "moniker": "", "website": "", "security_contact": "", "details": "" },
  "geoip": { "city": "", "country": "", "ip_address": "", "latitude": "", "longitude": "", "org": "", "postal": "", "region": "", "timezone": "" },
  "family_data": { "id": 0, "name": "", "description": "", "family_stake": 0, "members": 0 }
}
```

`geoip` and `family_data` MUST be `null` when the node is absent from the geodata cache or belongs to no family. `latitude`/`longitude` inside `geoip` MUST be strings (stringified floats), unlike the numeric `latitude`/`longitude` in the dVPN `location` object. `description` MUST fall back to an all-empty-strings object when no scraped description exists. A failure while aggregating the list MUST return 500.

`GET /explorer/v3/nym-nodes/{node_id}/delegations` MUST return a bare JSON **array** of `{ "amount": { "denom": "", "amount": "" }, "cumulative_reward_ratio": "", "block_height": 0, "owner": "", "proxy": null }`. It MUST return 404 with `No delegation data for node_id={node_id}` only when the node has no entry in the delegations cache (not bonded, or its chain query failed); a bonded node with zero delegations MUST return 200 with `[]`. A non-numeric `{node_id}` MUST be rejected by the path extractor with 400.

#### Scenario: Node with no delegators

- **GIVEN** a bonded node whose delegation query succeeded and returned nothing
- **WHEN** its delegations are requested
- **THEN** the response is 200 with `[]`

#### Scenario: Unbonded node

- **GIVEN** a node id absent from the delegations cache
- **WHEN** its delegations are requested
- **THEN** the response is 404 with the body `No delegation data for node_id=<id>`

#### Scenario: Undescribed node hidden

- **GIVEN** a bonded node with no stored self-description
- **WHEN** `GET /explorer/v3/nym-nodes` is called
- **THEN** the node is absent from the list and from `total`

### Requirement: The dVPN directory SHALL apply this exact filter, enrich, and sort pipeline

The dVPN gateway list MUST be built from the cached gateway list by, in order: (1) dropping gateways with `bonded=false`; (2) dropping gateways with `performance == 0`; (3) dropping gateways with no matching row in the nym-nodes table (matched by base58 ed25519 identity); (4) attaching family, staking and SOCKS5 percentile data; (5) dropping gateways whose `explorer_pretty_bond` or `self_described` JSON is missing or unparsable (a missing location or missing `build_information` therefore removes the node); (6) dropping gateways whose `location.two_letter_iso_country_code` is not exactly 2 characters; (7) sorting by `(two_letter_iso_country_code, identity_key)` ascending. Each item MUST be:

```json
{
  "identity_key": "<base58 ed25519>",
  "name": "<moniker>",
  "description": "<details>",
  "ip_packet_router": { "address": "" },        // or null
  "authenticator": { "address": "" },           // or null
  "location": {
    "two_letter_iso_country_code": "CH",
    "latitude": 0.0, "longitude": 0.0,
    "city": "", "region": "", "org": "", "postal": "", "timezone": "",
    "asn": { "asn": "", "name": "", "domain": "", "route": "", "kind": "residential" }
  },
  "last_probe": { "last_updated_utc": "", "outcome": { } },   // or null
  "ip_addresses": ["1.2.3.4"],
  "mix_port": 1789,
  "role": "EntryGateway",                       // or {"Mixnode":{"layer":1}} | "ExitGateway" | "Standby" | "Inactive"
  "entry": { "hostname": null, "ws_port": 9000, "wss_port": null },  // or null
  "bridges": { "version": "", "transports": [ { "transport_type": "quic_plain", "args": { } } ] },  // or null
  "performance": "0.95",
  "performance_v2": { "last_updated_utc": "", "score": "high", "mixnet_score": "high", "load": "low", "uptime_percentage_last_24_hours": 0.95 },
  "lewes_protocol_details": { "content": { "enabled": true, "control_port": 41264, "data_port": 51264, "x25519": "", "kem_keys": { } }, "signature": "" },
  "family_data": { "id": 0, "name": "", "description": "", "family_stake": 0, "members": 0 },
  "staking_data": { "total_stake": 0, "total_delegations": 0, "total_bond": 0, "delegations": 0 },
  "build_information": { },                     // full build-info object, same 10 fields as /v2/status/build_information
  "ports_check": { },                           // or null
  "last_ports_check_utc": ""                    // or null
}
```

`performance` MUST be the nym-api mixnet performance rendered as a fixed 2-decimal string (`performance / 100`, e.g. `"0.95"`, and `"2.55"` for an out-of-range stored value of 255). `location.asn.kind` MUST be `residential` when the upstream ASN type equals `isp` case-insensitively, otherwise `other`. `name` MUST be the moniker and `description` MUST be the details string from the scraped description (both `NA` when unscraped, and `description` is always present rather than null). `role`, `entry`, `ip_addresses` and `mix_port` MUST come from the matched nym-nodes row (so `role` uses externally-tagged enum encoding), whereas `ip_packet_router`, `authenticator`, `lewes_protocol_details` and `build_information` MUST come from the gateway's own stored self-description - `build_information.build_version` is also what the read-time version filter parses.

#### Scenario: Gateway missing from nym-nodes is dropped

- **GIVEN** a bonded gateway with nonzero performance that has no nym-nodes row
- **WHEN** the dVPN list is built
- **THEN** it is excluded and the discrepancy is logged as critical

#### Scenario: Invalid country code drops the node

- **GIVEN** a gateway whose geolocated country code is empty or longer than 2 characters
- **WHEN** the dVPN list is built
- **THEN** it is excluded

#### Scenario: Deterministic order

- **WHEN** the dVPN list is served
- **THEN** items are ordered by country code then identity key, so `countries` responses can rely on adjacency

### Requirement: The dVPN version filter SHALL apply at read time and only on the root route

The minimum node version MUST default to `1.6.2` and MUST be applied at read time by parsing each gateway's `build_information.build_version` as semver and keeping only versions `>=` the minimum; a gateway whose version does not parse MUST be dropped. Only `GET /dvpn/v1/directory/gateways` MUST accept a `min_node_version` query parameter; an unparsable value MUST return 400 with the body `Min version must be valid semver`. All other routes in the family (`/ips`, `/countries`, `/country/{cc}`, `/entry*`, `/exit*`) MUST use the `1.6.2` default and MUST ignore any `min_node_version` parameter. Because the filter runs at read time and the cache stores the unfiltered list, differing `min_node_version` values MUST NOT poison each other's results.

#### Scenario: Custom minimum version

- **WHEN** `GET /dvpn/v1/directory/gateways?min_node_version=1.9.0` is called
- **THEN** only gateways reporting a build version `>= 1.9.0` are returned, and a subsequent default-parameter call still returns the `>= 1.6.2` set

#### Scenario: Version parameter ignored elsewhere

- **WHEN** `GET /dvpn/v1/directory/gateways/entry?min_node_version=1.9.0` is called
- **THEN** the parameter has no effect and the `1.6.2` minimum applies

#### Scenario: Malformed version

- **WHEN** `GET /dvpn/v1/directory/gateways?min_node_version=latest` is called
- **THEN** the response is 400 with the body `Min version must be valid semver`

### Requirement: dVPN entry, exit, country and IP routes SHALL derive from the filtered list

`/entry` MUST return the gateways whose last probe reports `as_entry.can_route == true`; a `null` or untested `as_entry` MUST exclude the gateway. `/exit` MUST return the gateways whose last probe reports both `as_exit.can_route_ip_external_v4` and `as_exit.can_route_ip_external_v6`; a missing `as_exit` MUST exclude the gateway. `/countries`, `/entry/countries` and `/exit/countries` MUST return a bare array of the two-letter codes of the corresponding list with **adjacent** duplicates removed, which is exhaustive only because the list is sorted by country. `/country/{cc}`, `/entry/country/{cc}` and `/exit/country/{cc}` MUST filter by comparing the uppercased stored country code against the parsed country's alpha-2 code; the path segment MUST be parsed into a recognised country and an unrecognised value MUST be rejected by the path extractor with 400. `/ips` MUST return the sorted, deduplicated string forms of all `ip_addresses` of the default-minimum-version list, and it MUST be cached independently of any version parameter.

#### Scenario: Exit requires dual-stack routing

- **GIVEN** a gateway whose last probe can route external IPv4 but not IPv6
- **WHEN** `GET /dvpn/v1/directory/gateways/exit` is called
- **THEN** that gateway is excluded

#### Scenario: Country codes deduplicated

- **GIVEN** five gateways in `CH` and two in `DE`
- **WHEN** `GET /dvpn/v1/directory/gateways/countries` is called
- **THEN** the response is `["CH","DE"]`

#### Scenario: Unknown country segment

- **WHEN** `GET /dvpn/v1/directory/gateways/country/zz` is called
- **THEN** the path extractor rejects the request with 400

### Requirement: The dVPN probe payload SHALL be reshaped from the stored probe result

`last_probe` MUST be `{ "last_updated_utc": <gateway.last_testrun_utc or "">, "outcome": { ... } }` and the outcome MUST contain exactly the keys `as_entry`, `as_exit`, `wg`, `socks5`, `lp`, where:

- `as_entry` MUST be `{ "can_connect": bool, "can_route": bool }` when tested and `null` otherwise. Because the variant is untagged, "not tested" and "entry failure" both serialize to `null` and are indistinguishable on the wire, and a `null` read back is always interpreted as "not tested".
- `as_exit` MUST be `{ can_connect, can_route_ip_v4, can_route_ip_external_v4, can_route_ip_v6, can_route_ip_external_v6 }` or `null`.
- `wg` MUST be the WireGuard results object with the generic fields `can_register`, `can_handshake`, `can_resolve_dns`, `ping_hosts_performance`, `ping_ips_performance`, the v4 fields `can_query_metadata_v4`, `can_handshake_v4`, `can_resolve_dns_v4`, `ping_hosts_performance_v4`, `ping_ips_performance_v4`, the v6 fields `can_handshake_v6`, `can_resolve_dns_v6`, `ping_hosts_performance_v6`, `ping_ips_performance_v6`, and the download fields `download_duration_sec_v4`, `download_duration_milliseconds_v4`, `downloaded_file_size_bytes_v4`, `downloaded_file_v4`, `download_error_v4` plus their `_v6` counterparts; or `null`.
- `socks5` MUST always be present as `{ "can_proxy_https": bool, "score": <score>, "errors": [string]|null }`. When the stored probe has no `socks5` section, `can_proxy_https` MUST be derived from the percentile score (`false` only when the score is `offline`).
- `lp` MUST be `{ "can_connect": bool, "can_handshake": bool, "can_register": bool, "error": string|null }` or `null`.

All score values MUST serialize as the lowercase strings `offline`, `low`, `medium`, `high`. This outcome object MUST be treated as an externally-owned contract: the implementation carries an explicit warning that it is parsed by the VPN API, so its field names and score encodings cannot be changed or dropped without coordinating with that consumer, however arbitrary the scoring itself looks. Note that the raw `socks5` probe detail stored by agents (`can_connect_socks5`, `https_connectivity` with status code, latency and endpoint) is NOT exposed here; it is only visible through the raw `last_probe_result` on `/v2/gateways*`.

#### Scenario: Untested entry serializes as null

- **GIVEN** a probe result whose entry test was not run
- **WHEN** the dVPN gateway is served
- **THEN** `last_probe.outcome.as_entry` is `null`

#### Scenario: SOCKS5 section always present

- **GIVEN** a stored probe result with no `socks5` section and a percentile score of `medium`
- **WHEN** the dVPN gateway is served
- **THEN** `socks5` is `{ "can_proxy_https": true, "score": "medium", "errors": null }`

### Requirement: Stored probe results SHALL deserialize with schema fallback and back-filled WireGuard fields

Reading a stored probe result MUST first attempt the current `nym_gateway_probe` schema and then fall back to this crate's local schema; if both fail the gateway MUST be treated as having no probe (dropping it from entry/exit lists) rather than failing the request. After parsing, the WireGuard generic fields MUST be back-filled from their v4 counterparts when absent: `can_handshake` from `can_handshake_v4`, `can_resolve_dns` from `can_resolve_dns_v4`, `ping_hosts_performance` from `ping_hosts_performance_v4`, `ping_ips_performance` from `ping_ips_performance_v4`.

#### Scenario: Legacy probe schema

- **GIVEN** a stored probe result in the older local schema
- **WHEN** the API reads it
- **THEN** parsing falls back to that schema and the WireGuard v4 values are copied into the generic fields

### Requirement: Displayed scores SHALL be computed with these exact thresholds

`performance_v2.score` MUST be a weighted score of mixnet performance 40%, download speed 30% and IPv4 ping performance 30%, where the download-speed component is derived from `downloaded_file_size_bytes_v4` (default 1048576 bytes) over `download_duration_milliseconds_v4` (falling back to `download_duration_sec_v4 * 1000`) and bucketed as `>5 Mbps → 1.0`, `>2 → 0.75`, `>1 → 0.5`, `>0.5 → 0.25`, else `0.1`; when the probe has no WireGuard section both the download and ping components MUST be `0.0`. The weighted result MUST map `>0.75 → high`, `>0.5 → medium`, `>0.1 → low`, else `offline`. `performance_v2.mixnet_score` MUST be derived from mixnet performance alone with `>0.8 → high`, `>0.6 → medium`, `>0.1 → low`, else `offline`. `performance_v2.load` MUST be derived from `ping_ips_performance_v4` with `>0.8 → low`, `>0.4 → medium`, else `high`, and MUST be forced to `offline` whenever `score` is `offline`. `performance_v2.uptime_percentage_last_24_hours` MUST be the mixnet performance as a 0..1 float. The SOCKS5 percentile score MUST be computed across the whole gateway set from `https_connectivity.https_latency_ms` (absent or `null` counts as 0): every gateway with latency 0 MUST be `offline`, and the remainder sorted ascending MUST be bucketed as the fastest `ceil(n/2)` → `high`, up to `ceil(3n/4)` → `medium`, the rest → `low`.

#### Scenario: Zero-latency SOCKS5 scores offline

- **GIVEN** a gateway whose SOCKS5 HTTPS latency is 0 or missing
- **WHEN** the percentile score is computed
- **THEN** the gateway scores `offline`

#### Scenario: Offline score forces offline load

- **GIVEN** a gateway whose weighted score is `offline`
- **WHEN** `performance_v2` is built
- **THEN** `load` is also `offline` irrespective of ping performance

#### Scenario: Four online gateways bucket 2/1/1

- **GIVEN** four gateways with latencies 100, 200, 300, 400 ms
- **WHEN** percentile scores are computed
- **THEN** they are `high`, `high`, `medium`, `low` respectively

### Requirement: Read endpoints SHALL be served from capacity-1 TTL caches that are not populated with empty results

The gateway list, dVPN gateway list, dVPN gateway IPs, nym-nodes list, mixnode stats, summary history and session stats MUST each be served from their own `moka` cache with max capacity 1 and time-to-live `nym_http_cache_ttl` (default 30s). On a miss the value MUST be rebuilt from the database, stored (except as noted) and returned. An empty gateway list, empty dVPN list and empty nym-nodes list MUST NOT be cached, so an empty database causes a rebuild on every request. `GET /v2/summary` MUST bypass caching entirely. Failures during a rebuild MUST behave asymmetrically: a failed read of the `gateways` table MUST panic the handler task (`Cannot read gateways table`), and inside the dVPN rebuild a failed read of `nym_nodes`, the node-families tables or the bond-info column MUST likewise panic; the explorer nym-nodes aggregation MUST instead return 500; and mixnode stats, summary history and session stats MUST degrade to empty lists (which are then cached for the TTL).

#### Scenario: Cache hit within TTL

- **GIVEN** a cached gateway list within its TTL
- **WHEN** `GET /v2/gateways` is called
- **THEN** the cached list is paginated and returned without a database read

#### Scenario: Empty list is not cached

- **GIVEN** an empty gateways table
- **WHEN** `GET /v2/gateways` is called twice
- **THEN** both calls query the database and both return `total: 0`

#### Scenario: dVPN list rebuild cost

- **GIVEN** an expired dVPN cache
- **WHEN** any `/dvpn/v1/directory/gateways*` route is called
- **THEN** the whole list is rebuilt (gateways, nym-nodes, families, bond info, SOCKS5 percentiles) before the route-specific filter is applied

### Requirement: The OpenAPI document SHALL be generated from the handlers, with known gaps

`GET /api-docs/openapi.json` MUST serve a document titled `Node Status API`, generated by `utoipauto` from the `#[utoipa::path]` annotations, and Swagger UI MUST be mounted at `/swagger`. The document is descriptive, not normative: it MUST NOT be treated as the compatibility contract because `/dvpn/v1/directory/gateways/ips` and all `/internal/testruns*` routes carry no annotation and are therefore absent, and `/explorer/v3/nym-nodes/{node_id}/delegations` is annotated with the singular `NodeDelegation` while the handler returns an array.

#### Scenario: Undocumented routes still served

- **WHEN** the OpenAPI document is compared against the route table
- **THEN** `/dvpn/v1/directory/gateways/ips` and the `/internal/testruns*` routes are missing from the document but are served by the API

## Technical Notes

- **Implementation**: `http/server.rs` (`start_http_api`, binds `0.0.0.0:{http_port}`, also spawns the ports-check scheduler), `http/api/mod.rs` (`RouterBuilder`, CORS, request logging), `http/state.rs` (`AppState`, `HttpCache`, `aggregate_node_info_from_db`, `load_family_lookup`), `http/mod.rs` (`PagedResult`, `Pagination`), `http/models/mod.rs` (`Gateway`, `GatewaySkinny`, `DVpnGateway`, `ExtendedNymNode`, `Service`, `SessionStats`, `NodeDelegation`, `Location`, `NodeFamilyInformation`, `NodeStakeInformation`), `http/models/gw_probe/` (probe reshaping, scoring, `socks5_calc.rs`), `http/error.rs`, `db/models.rs` (`GatewayDto → Gateway`, ports-check normalisation, `NetworkSummary`), `db/queries/summary.rs`.
- **Framework**: axum 0.8 + tower-http CORS; OpenAPI via utoipa 5 / utoipa-swagger-ui / utoipauto; caching via moka; JSONPath via serde_json_path; country parsing via celes; version comparison via semver.
- **Compatibility hazards for a replacement**: the plain-text error bodies (especially the `No testruns available` 503 body the agent matches on), the echoed-input 400 bodies, hardcoded `routing_score`/`config_score`/`Service.routing_score`, the `page`/`size` clamping quirks and the `size=0` panic, `null`-collapsed `as_entry` variants, `min_node_version` being honoured on only one route, `/ips` ignoring the version filter after its first fill, and the delegations endpoint returning an array while advertising an object.
- **Known behaviour**: `get_gateway_list` and the dVPN rebuild panic when the gateways/nym_nodes tables cannot be read (treated as unrecoverable); several handlers log at `CRITICAL`-style error level and continue, silently shrinking the dVPN list.
- **Related specs**: reads persisted data from [[node-status-api-persistence]]; enriched by [[node-status-api-monitoring]]; internal endpoints specified in [[node-status-api-testruns]]; probe result shapes come from [[gateway-probe]]; agent behaviour in [[node-status-agent]].
