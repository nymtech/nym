# node-status-api-testruns Specification

> Generated by openlore on 2026-07-07
> Source files: `nym-node-status-api/nym-node-status-api/src/testruns/{mod,queue,models}.rs`, `http/api/testruns.rs`, `http/state.rs`, `http/server.rs`, `db/queries/testruns.rs`, `db/models.rs`

## Purpose

Defines gateway test-run orchestration: a background queuer that enqueues probe and ports-check test runs for bonded gateways, and the authenticated `/internal/testruns` API that assigns test runs to external agents (attaching ecash ticket materials) and ingests their signed results.

## Requirements

### Requirement: The background queuer SHALL enqueue idempotent probe test runs and re-queue stale ones

The test-run queuer MUST loop: re-queue stale in-progress test runs (those assigned before the stale window, default 7200s), then iterate all gateways ordered by last-testrun time, filter to bonded gateways, and queue a probe run per gateway, then sleep the refresh interval (default 450s). Enqueue MUST be idempotent — if a non-complete Probe run already exists for a gateway it MUST be reused rather than duplicated; otherwise a new `Queued`/`Probe` row is inserted. Unknown gateways MUST be rejected.

#### Scenario: Idempotent enqueue
- **GIVEN** a bonded gateway that already has a non-complete Probe test run
- **WHEN** the queuer processes it
- **THEN** the existing run is reused and no duplicate is inserted

#### Scenario: Stale in-progress run re-queued
- **GIVEN** an in-progress test run older than the stale window
- **WHEN** the queuer refreshes stale runs
- **THEN** it is set back to Queued so it can be reassigned

### Requirement: A scheduler SHALL periodically enqueue due ports-check test runs

A ports-check scheduler MUST run every 10 minutes (unless disabled by `PORTS_CHECK_SCHEDULER_ENABLED=false`) and enqueue `Queued`/`PortsCheck` rows for bonded gateways whose last ports check is null or older than 14 days, deduplicating against any pending PortsCheck run.

#### Scenario: Overdue ports check enqueued
- **GIVEN** a bonded gateway whose last ports check is older than 14 days and has no pending PortsCheck run
- **WHEN** the scheduler runs
- **THEN** a `Queued`/`PortsCheck` test run is inserted for it

### Requirement: Testrun assignment SHALL require agent authentication, freshness, capacity, and ticketbooks

`GET /internal/testruns/` and `GET /internal/testruns/ports-check` MUST: authenticate the request (agent public key registered in the configured `agent_key_list` and a valid ed25519 signature); enforce request freshness (reject requests whose timestamp is older than the freshness window, default 120s); reject when the in-progress count is at or above `agent_max_count` (503); take the assignment mutex to serialize assignment; require enough ticketbooks of all buffered types; then atomically claim the oldest queued run for a bonded gateway (performance > 0) using `FOR UPDATE ... SKIP LOCKED`; attach ticket materials; and return a `TestrunAssignmentWithTickets`.

#### Scenario: Unregistered agent rejected
- **GIVEN** a request signed by a public key not in `agent_key_list`
- **WHEN** it requests a test run
- **THEN** the API returns 401 (unauthorized)

#### Scenario: Stale request rejected
- **GIVEN** a signed request whose timestamp is older than the freshness window
- **WHEN** it is received
- **THEN** it is rejected as not fresh

#### Scenario: Capacity limit reached
- **GIVEN** the in-progress test-run count is at `agent_max_count`
- **WHEN** an agent requests a test run
- **THEN** the API returns 503 without assigning

#### Scenario: Atomic oldest-run claim
- **GIVEN** multiple agents requesting concurrently
- **WHEN** each claims a test run
- **THEN** the oldest queued run for a bonded gateway is claimed exactly once via `SKIP LOCKED`, with ticket materials attached

### Requirement: Probe result submission SHALL validate assignment identity and timestamp before completing

`POST /internal/testruns/{id}` (v1) MUST validate that the test run is in-progress and its `assigned_at_utc` matches the stored assignment timestamp, resolve the gateway, serialize the probe result, mark the run Complete, and update the gateway's last probe log/result and score, returning 201. A timestamp mismatch MUST return 400. The `POST /internal/testruns/{id}/v2` variant MUST, when the test-run id is unknown, create an "external" gateway and in-progress test run before processing.

#### Scenario: Timestamp mismatch rejected
- **GIVEN** an in-progress test run whose stored `assigned_at_utc` differs from the submitted value
- **WHEN** results are submitted
- **THEN** the API returns 400 and the run is not completed

#### Scenario: External result via v2
- **GIVEN** a submission for an unknown test-run id on the v2 endpoint
- **WHEN** it is received
- **THEN** the gateway is created if needed, an external in-progress run is inserted, and the result is processed to completion (201)

### Requirement: Ports-check submission SHALL validate kind and persist only the compact result

`POST /internal/testruns/{id}/ports-check/v2` MUST follow the same identity/timestamp validation, MUST validate that the run kind is PortsCheck, and MUST store only the compact ports-check JSON against the gateway — the probe log MUST NOT be persisted for ports checks. It MUST return 201.

#### Scenario: Wrong kind rejected
- **GIVEN** a ports-check submission targeting a test run whose kind is Probe
- **WHEN** it is received
- **THEN** the request is rejected

#### Scenario: Probe log not persisted for ports checks
- **WHEN** a ports-check result is submitted
- **THEN** only the compact ports-check JSON is stored and the probe log is discarded
