# node-status-api-persistence Specification

> Generated by openlore on 2026-07-07
> Source files: `nym-node-status-api/nym-node-status-api/src/db/{mod,models}.rs`, `db/queries/{gateways,gateways_stats,nym_nodes,node_families,packet_stats,scraper,summary,testruns,ecash_data,misc}.rs`, `cli/mod.rs`

## Purpose

Defines the PostgreSQL persistence layer of the node status service: the connection pool and migrations, the DTO/insert models, and the per-table query modules. It backs the HTTP read API and is written by the monitor, scrapers, test-run orchestration, and ticketbook manager.

## Requirements

### Requirement: Storage SHALL initialise a PostgreSQL pool and run migrations

`Storage::init` MUST build a `sqlx` PostgreSQL pool using the configured `DATABASE_URL` and pool bounds (busy timeout 5s, max 20, min 5 connections by default), optionally enabling TLS via `PG_CERT`, and MUST run the migrations in `./migrations_pg` unless `SKIP_MIGRATIONS=true`. Statement logging MUST be disabled.

#### Scenario: Migrations run on init
- **GIVEN** a reachable database and `SKIP_MIGRATIONS` unset
- **WHEN** `Storage::init` runs
- **THEN** the connection pool is built and the `./migrations_pg` migrations are applied

#### Scenario: Migrations skipped when requested
- **GIVEN** `SKIP_MIGRATIONS=true`
- **WHEN** `Storage::init` runs
- **THEN** migrations are not applied

### Requirement: Directory snapshots SHALL be refreshed with a null-then-upsert pattern

Refreshing the gateways and nym-nodes tables MUST run in a transaction that first clears the "present" markers (sets all gateways `bonded=false`, or nulls all nym-node `self_described`/`bond_info`) and then upserts the currently-present nodes, so nodes absent from the latest directory are correctly marked not-present. Node families MUST be refreshed by delete-all-then-batch-reinsert, relying on `ON DELETE CASCADE` for members.

#### Scenario: Departed gateway marked unbonded
- **GIVEN** a gateway present in a prior snapshot but absent from the current directory
- **WHEN** `update_bonded_gateways` runs
- **THEN** that gateway ends the transaction with `bonded=false`

### Requirement: Concurrent claims SHALL use row locking to avoid double assignment

Queries that claim a unit of work or spend a resource MUST use `FOR UPDATE ... SKIP LOCKED` (test-run assignment) or an atomic conditional update (next unspent ticketbook) so concurrent workers/agents never claim the same row twice.

#### Scenario: Two agents cannot claim the same test run
- **GIVEN** two concurrent assignment queries
- **WHEN** both execute
- **THEN** `SKIP LOCKED` ensures each claims a different queued test run

### Requirement: Time-series data SHALL accumulate daily and prune stale rows

Daily packet-mixing stats MUST accumulate packet counts on conflict (overwriting stake), and MUST be derived from the second-most-recent raw stats row as the delta baseline. Session-stat records MUST be immutable (insert `ON CONFLICT DO NOTHING`) and old records MUST be prunable by cutoff date. Summary history MUST upsert one row per UTC day (the same day's row refreshed each cycle).

#### Scenario: Daily stats accumulate on conflict
- **GIVEN** an existing daily-mixing-stats row for a node and day
- **WHEN** a new delta is inserted
- **THEN** packet counts are accumulated and stake overwritten rather than duplicating the row

#### Scenario: Sessions are immutable
- **WHEN** a session record that already exists is inserted again
- **THEN** the insert is a no-op (`ON CONFLICT DO NOTHING`)

### Requirement: Summary reads SHALL require the full set of summary keys

`get_summary` MUST validate that all summary keys are present and MUST surface a 500-class error if any are missing, rather than returning a partial summary.

#### Scenario: Missing summary key
- **GIVEN** the summary table is missing one of its required keys
- **WHEN** `get_summary` runs
- **THEN** it returns an internal error rather than a partial `NetworkSummary`

### Requirement: Node classification SHALL distinguish gateways from mixing nodes for scraping and writes

`get_nodes_for_scraping` MUST classify a node as an entry/exit nym-node when its ed25519 key matches a bonded gateway, else as a mixing nym-node; scraped descriptions for entry/exit nodes MUST be written to both the nym-node and gateway description tables.

#### Scenario: Gateway node written to both tables
- **GIVEN** a scraped node whose key is a bonded gateway
- **WHEN** its description is stored
- **THEN** the description is written to both the nym-node and gateway description tables

## Technical Notes

- **Implementation**: `db/mod.rs` (`Storage::init`, pool, migrations), `db/models.rs` (DTOs, `TestRunStatus`/`TestRunKind` enums, self-described de-helpers with `#[serde(default)]` for forward-compat, ports-check normalization), `db/queries/*` (per-table modules).
- **Engine**: PostgreSQL only, via `sqlx` (`runtime-tokio-rustls`) with compile-time-checked `query!`/`query_scalar!` macros; migrations in `./migrations_pg`.
- **Known risks**: several unix timestamps are stored as `i32` (year-2038 truncation risk); `get_raw_node_stats` reads the second-most-recent row (`LIMIT 1 OFFSET 1`) as the delta baseline.
- **Related specs**: written by [[node-status-api-monitoring]], [[node-status-api-testruns]], [[node-status-api-ticketbook]]; read by [[node-status-api-http]].
